## 2026-08-02 - O(N*M) bottlenecks with context helpers inside maps
**Learning:** Found a critical performance bottleneck in `EmployeeManagement.tsx` where an O(N) context helper (`getUserAssignments`) was being called inside an O(N) `.map` and `.reduce` functions across the employee list, resulting in synchronous O(N*M) complexity during renders. This was causing slow interactions, particularly when typing in the search bar.
**Action:** Instead of relying on the abstracted helper function inside loops, bypass it and precompute a `Map` in a single O(N) pass using `useMemo`. This allows subsequent O(1) lookups during the list render, significantly reducing main thread blocking. Also always wrap derived array filtering (like `employees.filter(...)`) in `useMemo` so it doesn't run on every state change.
