## 2025-02-12 - Refactor O(N*M) Context Helpers in Rendering Loops
**Learning:** Found a critical performance bottleneck where the `employeeStats` helper function queried a filtered list (`getUserAssignments`) on every render for each employee in a loop. This caused an O(N*M) traversal because `getUserAssignments` inherently iterated over all assignments again. If multiple statistics were calculated using this pattern (e.g. `totalCompleted` and `totalInTraining`), the performance hit grew exponentially as the dataset increased.
**Action:** When computing properties that require filtering or traversing global arrays inside list components, do not use context helpers that perform array filtering under the hood. Instead, memoize the derived arrays (e.g. `employees`), construct a single-pass O(N) frequency lookup map (using `React.useMemo` to ensure dependency arrays are stable), and use `React.useCallback` for the refactored lookup function. For calculating total summaries across a list, collapse multiple array loops (e.g. chaining `.map`, `.filter`, or `.reduce`) into a single `reduce` pass that computes all fields simultaneously.
