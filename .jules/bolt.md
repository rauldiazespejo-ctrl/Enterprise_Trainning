## 2024-09-30 - O(1) Maps and Lazy Stats in Paginated React Components
**Learning:** In list/management React components with pagination, eager computation of derived stats for all items upfront in a global `useMemo` causes performance regressions when expensive context helpers are involved, because they get calculated for non-rendered rows. Furthermore, entirely flattening O(N*M) loops can violate encapsulation if it requires bypassing existing context helper functions.
**Action:** When optimizing performance in paginated components, compute per-item stats lazily/on-demand for the currently paginated rows, but build frequency/lookup Maps (using `useMemo` in a single pass) for raw data arrays to allow fast O(1) lookups alongside the existing context helpers. Always wrap the existing O(N*M) aggregation logic inside a `React.useMemo` block to prevent recalculation on every render while strictly preserving encapsulation.
