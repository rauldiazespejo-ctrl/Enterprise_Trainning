## 2023-10-24 - Avoiding O(N*M) context helper lookups in render loops
**Learning:** Calling context helper functions (like `getUserAssignments`) inside a loop during render creates a hidden O(N*M) performance anti-pattern. Instead of using a helper that filters an array for each item in a loop, processing the full raw array directly in a single pass to build a frequency map, and memoizing the result, achieves O(N+M) complexity and prevents excessive re-renders.
**Action:** When needing derived state across large collections in a loop, refactor to build a single memoized lookup map (e.g., using `reduce` or iterating the raw array once) instead of calling filter-based helper functions inside the map/reduce callbacks. Ensure object lookups include fallback default values to maintain the guaranteed return signature.
