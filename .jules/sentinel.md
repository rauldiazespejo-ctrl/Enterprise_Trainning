## 2024-09-02 - Missing Auth in Audit Log Edge Function
**Vulnerability:** The `audit-log` Supabase Edge Function allows unauthenticated requests to insert audit log entries without validation. It reads `user_id` from the request body. This allows an attacker to spoof audit log entries, potentially covering their tracks or falsely framing another user for actions.
**Learning:** Security controls on audit endpoints are often overlooked, especially if the audit log system itself is designed to record 'failed access' or other pre-authentication events. If the function isn't authenticated, the data is entirely untrusted.
**Prevention:** Edge Functions should extract the `Authorization` header and validate the JWT token via `auth.getUser()` to ensure the request is authenticated, unless explicitly designed to handle unauthenticated logs (e.g. login failures), which should be securely differentiated from authenticated actions.
## 2024-09-02 - Unauthenticated SSRF in scrape-url Edge Function
**Vulnerability:** The `scrape-url` Supabase Edge Function takes a `url` parameter from an unauthenticated request body and fetches it directly using `fetch(url)`. This allows an attacker to bypass CORS or network segmentation to probe internal networks (e.g. `localhost`, `169.254.169.254`, `10.0.0.1`) from the Supabase environment, potentially leaking internal data or metadata endpoints. It's unauthenticated so anyone can hit it.
**Learning:** Functions designed to fetch external content are highly prone to Server-Side Request Forgery (SSRF) if they don't strictly validate the URL structure and hostname against internal/private ranges. Because Deno uses `fetch`, an attacker could also redirect requests.
**Prevention:** URL parameters must be parsed via `new URL()`. The protocol must be restricted to `http:` or `https:`. The hostname must be validated against local, private, internal, and cloud metadata IP address ranges and hostnames before executing the `fetch`. If possible, the function should also be authenticated.
