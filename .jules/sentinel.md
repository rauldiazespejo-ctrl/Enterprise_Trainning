## 2025-03-05 - IDOR in Edge Functions using Service Role Keys
**Vulnerability:** In Supabase Edge Functions, using the `SUPABASE_SERVICE_ROLE_KEY` bypasses Row Level Security. The `audit-log` function was trusting the `user_id` provided in the request body, allowing any user to spoof the identity of another user in the audit logs by providing a different user's ID.
**Learning:** Relying on user-provided data for identity is a significant IDOR vulnerability, particularly in serverless/edge functions that use elevated privileges (like service role keys) and lack standard RLS enforcement. Even mixed-context endpoints (handling both authenticated and unauthenticated actions) must securely verify identity when a session is present.
**Prevention:** Always verify the user's identity securely from the `Authorization` header using `supabase.auth.getUser()`. Maintain codebase consistency by instantiating a dedicated `callerClient` using `createClient` with the `SUPABASE_ANON_KEY` and the `Authorization` header rather than passing the JWT to the admin client. For mixed-context endpoints, strictly define and allowlist the actions that can bypass the session check.
