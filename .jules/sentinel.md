## 2024-05-24 - Edge Function IDOR via Untrusted Body Payload
**Vulnerability:** The `audit-log` Supabase Edge Function previously accepted the `user_id` from the unverified request body for all actions, allowing malicious actors to spoof audit logs by sending a different `user_id` than their own.
**Learning:** This occurred because edge functions designed to handle a mix of authenticated and unauthenticated actions (like `login_failed`) failed to explicitly differentiate and enforce token validation for the authenticated actions. It trusted the body payload implicitly.
**Prevention:** Always implement a "fail-closed" mechanism in Edge Functions. Require the `Authorization` header and verify it using `callerClient` (created with `anonKey` and the provided token). Only bypass this check for a strict whitelist of unauthenticated actions (e.g., `['login', 'signup']`). For authenticated actions, always overwrite any body-provided `user_id` with the trusted `user.id` from the verified token.
