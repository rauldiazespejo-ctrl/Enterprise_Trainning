## 2024-03-24 - SSRF in scrape-url Edge Function
**Vulnerability:** The `scrape-url` Supabase Edge Function directly fetched URLs provided by users without validating whether they resolved to internal or private IP addresses, allowing for Server-Side Request Forgery (SSRF).
**Learning:** Edge functions are typically executed on shared or internal networks. Directly calling `fetch` on user-supplied URLs can allow attackers to scan internal networks, access metadata endpoints, or hit private services. Using basic regex validation on the URL string is not enough, as attackers can provide a domain that resolves to a private IP (DNS Rebinding) or use HTTP redirects to bypass initial URL checks.
**Prevention:** To avoid this, always implement comprehensive URL validation before fetching. Ensure the scheme is HTTP/HTTPS. Explicitly resolve the domain using DNS (e.g., `Deno.resolveDns`) and check that none of the resolved IPs are in the private range. Furthermore, handle HTTP redirects manually by setting `redirect: 'manual'` in the `fetch` options, cancelling discarded response bodies to prevent resource leaks, and recursively validating and fetching the new location.
