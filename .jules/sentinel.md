## 2024-06-25 - Fix IDOR in audit-log edge function
**Vulnerability:** The `audit-log` Supabase Edge Function previously accepted the `user_id` blindly from the incoming JSON request payload and used it to log actions using the admin client. This allowed unauthenticated or authenticated users to spoof audit logs as any other user (IDOR/spoofing).
**Learning:** When using the Supabase Service Role Key (which bypasses Row Level Security), the system fully trusts the input. If the request body provides the user identity instead of deriving it securely from the authentication session token, a user can forge their identity. This is a common risk when logging events on behalf of users in edge functions or backend services.
**Prevention:** In edge functions handling mixed context events, always fetch and overwrite user identifiers directly from the secure `Authorization` header by calling `supabase.auth.getUser()`. Only allow bypasses for explicitly permitted unauthenticated actions (like `login_failed` or `signup`).
