## 2025-02-27 - SSRF Vulnerability via Web Scraper Redirects
**Vulnerability:** The `scrape-url` Supabase edge function accepted arbitrary URLs and fetched them directly, allowing access to internal/private networks via SSRF (Server-Side Request Forgery). Simple IP blocks were bypassable via redirects.
**Learning:** Even if the initial user-provided URL resolves to an external IP, standard `fetch` transparently follows redirects. Attackers can provide a benign external URL that redirects the edge function to an internal IP or metadata service (like `169.254.169.254`). Relying on simple initial validation is insufficient. The `URL` constructor effectively normalizes IP address obfuscations (octal, hex, decimal) making hostname checking viable if done at each redirect step.
**Prevention:** When proxying or scraping URLs on the server, configure `fetch` with `{ redirect: 'manual' }`. Intercept `3xx` redirects, extract the `Location` header, and explicitly re-validate the new URL against an IP/hostname blocklist *before* continuing the request chain.
