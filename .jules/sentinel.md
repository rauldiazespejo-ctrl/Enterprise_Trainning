## 2024-10-06 - IDOR Vulnerability in Audit Log Edge Function
**Vulnerability:** The `audit-log` Supabase Edge Function previously accepted any `user_id` provided in the request body to log events, because it used the `SUPABASE_SERVICE_ROLE_KEY` to insert records without verifying the user's `Authorization` header. This allowed malicious actors to spoof audit logs for other users (Insecure Direct Object Reference).
**Learning:** In Supabase Edge Functions, using the `service_role` key bypasses Row Level Security (RLS). When accepting user IDs from the client payload under these conditions, the function implicitly trusts the client. This is insecure for endpoints handling sensitive records like audit logs.
**Prevention:** Always verify the authenticated user's JWT from the `Authorization` header using `supabase.auth.getUser()` when using the `service_role` key for administrative inserts. Overwrite any client-provided `user_id` with the securely retrieved authenticated user ID to prevent IDOR and spoofing. For unauthenticated events like logins, handle them as explicit bypasses while still validating the general structure.
