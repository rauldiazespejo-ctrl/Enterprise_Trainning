## 2025-02-15 - Missing Authentication & IDOR in Supabase Edge Functions with Service Role Key
**Vulnerability:** The `audit-log` edge function used the `SUPABASE_SERVICE_ROLE_KEY` to insert records, bypassing RLS. However, it completely lacked an authentication check, meaning anyone could call the function. Furthermore, it blindly trusted the `user_id` passed in the request body, allowing an attacker to spoof audit log entries as any user.
**Learning:** Using the service role key in an edge function inherently bypasses database RLS. When an edge function acts on behalf of a user, it must manually extract and verify the user's session token (`Authorization` header) before taking action, especially when it receives sensitive fields like `user_id` from the client.
**Prevention:** When an edge function uses `SUPABASE_SERVICE_ROLE_KEY`, always enforce authentication by initializing a secondary Supabase client with the `SUPABASE_ANON_KEY` and the caller's `Authorization` header. Retrieve the authenticated user's details via `callerClient.auth.getUser()` and use those server-verified details (e.g., `user.id`) rather than client-provided payloads. Allow-list unauthenticated actions only when strictly necessary.
