## 2024-11-10 - [CRITICAL] Fix SSRF in scrape-url edge function
**Vulnerability:** Server-Side Request Forgery (SSRF) vulnerability in the `scrape-url` edge function. The function fetched user-provided URLs without validating if they resolved to internal or private IP addresses, allowing potential access to internal network resources.
**Learning:** Edge functions that fetch external resources based on user input are prime targets for SSRF. The default `fetch` behavior automatically follows redirects, which can be abused to bypass simple hostname checks if the external server redirects to an internal IP. Additionally, IP resolution can resolve to private network ranges.
**Prevention:** Always set `redirect: 'manual'` in `fetch` options when fetching user-provided URLs to intercept and validate redirects. Implement DNS resolution checks (using `Deno.resolveDns` for both 'A' and 'AAAA' records) on every hop to block internal/private IPs (e.g., `127.0.0.1`, `10.x.x.x`, `192.168.x.x`). Ensure discarded responses are properly canceled (e.g., `response.arrayBuffer()`) to prevent resource leaks.
