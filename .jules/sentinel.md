## 2024-05-31 - IDOR in Audit Log Edge Function
**Vulnerability:** The `audit-log` edge function was susceptible to Insecure Direct Object Reference (IDOR). An attacker could forge audit logs by supplying an arbitrary `user_id` in the request body because the function failed to authenticate or validate the author of the request.
**Learning:** Initializing critical entity identifiers (like `user_id`) from a client-provided JSON body before enforcing an active authentication check results in a "fail-open" scenario. Omitting the `Authorization` header completely bypassed any subsequent enforcement if the API design assumes a valid token implies correct ownership but leaves the unauthenticated path unprotected.
**Prevention:** Strictly implement a "fail-closed" mechanism for sensitive edge functions. Never trust the request body for `user_id`; always extract it from the authenticated JWT token using `getUser()`. Explicitly throw `Unauthorized` errors for missing headers unless the action is strictly defined in an exempt list (like `login_failed` or `logout`).
