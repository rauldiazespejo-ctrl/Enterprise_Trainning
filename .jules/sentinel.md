## 2024-08-11 - [CRITICAL] Prevent SSRF in Supabase Edge Functions
**Vulnerability:** Server-Side Request Forgery (SSRF) in `scrape-url` where user-provided URLs were fetched directly without validation against internal/private IP ranges or local hostnames.
**Learning:** Supabase Edge Functions (and similar serverless environments) execute in a network context that might have access to internal metadata services or other internal cloud resources. Fetching arbitrary user-provided URLs allows attackers to probe the internal network or access sensitive instance metadata if the environment is not locked down.
**Prevention:** Always parse untrusted URLs using `new URL()` (which normalises octal and hex IP representations), ensure the protocol is strictly `http:` or `https:`, and explicitly validate the parsed hostname to block access to internal, private, and loopback ranges (e.g., `127.0.0.0/8`, `10.0.0.0/8`, `192.168.0.0/16`, `172.16.0.0/12`, `169.254.169.254`, `0.0.0.0`, `localhost`, and `::1`).
