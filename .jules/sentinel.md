
## 2024-05-18 - SSRF Vulnerability in Scrape-URL Function
**Vulnerability:** The `scrape-url` Supabase Edge Function directly passed user-provided URLs to `fetch` without any validation or sanitization, introducing a severe Server-Side Request Forgery (SSRF) vulnerability. This could allow an attacker to probe internal networks, access private IP space (e.g., AWS Metadata endpoints like `169.254.169.254`, `localhost`, etc.), or bypass intended restrictions.
**Learning:** Functions designed to proxy or scrape external web content must always enforce strict URL validation prior to issuing HTTP requests. Never blindly trust user input to reach out to external servers. Using `new URL()` alone is insufficient; explicit checks against the protocol and hostname are required to prevent SSRF bypasses via IP obfuscation or local loopbacks.
**Prevention:** Implement a dedicated URL validation function (like `isValidExternalUrl`) that: 1) Verifies the protocol is HTTP/HTTPS. 2) Explicitly blocks local hostnames (`localhost`, `[::1]`, `.local`). 3) Detects and blocks requests to internal/private IP ranges (`127.0.0.0/8`, `10.0.0.0/8`, `192.168.0.0/16`, `172.16.0.0/12`, `169.254.169.254`). Always apply this validation before executing `fetch` with a user-provided URL.
