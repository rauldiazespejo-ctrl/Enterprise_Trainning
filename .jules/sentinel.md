## 2023-10-27 - Server-Side Request Forgery (SSRF) and Auth Bypass in scrape-url
**Vulnerability:** The `scrape-url` Supabase function lacked authentication, allowing unauthenticated users to invoke it. Additionally, it took an arbitrary URL and performed a fetch request without validating the domain or protocol, exposing the function to Server-Side Request Forgery (SSRF) vulnerabilities where attackers could make the server request internal IP addresses or cloud metadata.
**Learning:** This occurred because the function was originally designed to fetch arbitrary public webpages for course generation but lacked critical validation on the inputs and authorization checks on the invoker. The function trusted the user-provided URL blindly.
**Prevention:** Always explicitly validate authentication in Edge Functions by extracting the `Authorization` header and using `auth.getUser()`, adhering to the 'Fail Closed' security principle. For URL fetching, implement SSRF protection by parsing the URL with `new URL()`, verifying the protocol is HTTP/HTTPS, and explicitly blocking requests to local, private, internal, and cloud metadata IP addresses or hostnames (e.g., localhost, 127.0.0.0/8, 10.0.0.0/8, 192.168.0.0/16, 172.16.0.0/12, 169.254.169.254, [::1], and .local). Ensure string-based IPv4 validation checks use strictly numeric parts to prevent bypasses.
