## 2024-03-20 - IDOR in audit-log via spoofed user_id
**Vulnerability:** The `audit-log` edge function was extracting the `user_id` from the request body instead of the authorization token (JWT), making it vulnerable to IDOR. Any authenticated (or unauthenticated, if the token wasn't checked) user could submit an audit log with an arbitrary `user_id` in the body, spoofing the identity of another user in the audit logs.
**Learning:** For actions requiring a user context, it's critical to derive identity directly from a securely verified token (like `supabase.auth.getUser()`) rather than trusting client-provided input in the payload. However, exempt actions (like login attempts) might genuinely lack a valid JWT and need fallback support to log the activity properly.
**Prevention:** Always extract `user_id` from the authorization header (JWT) using `callerClient.auth.getUser()`. Implement a fail-closed mechanism to reject unauthorized requests, while allowing specific fallback extraction for unauthenticated edge cases (e.g., failed logins) to maintain audit trail context without allowing impersonation.
