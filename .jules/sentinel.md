## 2025-03-05 - Prevent IDOR in Supabase Edge Functions
**Vulnerability:** The `audit-log` Edge Function relied on a `user_id` passed in the client payload for tracking security events, which an attacker could easily spoof, causing an Insecure Direct Object Reference (IDOR).
**Learning:** Because the Edge Function used the `SUPABASE_SERVICE_ROLE_KEY` to insert records (bypassing Row Level Security), any unauthenticated or malicious user could inject arbitrary `user_id` values unless the payload was strictly verified against the `Authorization` header.
**Prevention:** In functions using the service role key, do not trust client-provided user IDs. Always instantiate a dedicated `callerClient` using the `SUPABASE_ANON_KEY` and the `Authorization` header to call `callerClient.auth.getUser()`, explicitly overriding the payload's `user_id`. Safely bypass this check for unauthenticated actions (e.g. `login_failed`) by falling back to the payload value. Separating `const` and `let` for payload variables avoids `prefer-const` linting errors.
